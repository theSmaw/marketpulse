- **Write `docs/adr/0008-*` and add the row to `docs/adr/README.md`.** They are numbered in the order written and never renumbered. Context, decision, rejected alternatives, consequences — the consequences are the part that earns its keep. The decisions this story produces:
  - **How the pair is made legible** — Task 1.8.2 concluded, so this is a decision to record rather than a question to resolve: two `pino-pretty` options (`singleLine`, `translateTime: "SYS:h:MM:ss.l TT"`), a request from **12 rendered lines to 2**, no dependency and no change to `scripts/dev.sh`. Two consequences belong in the write-up: **a stack is still multi-line**, so the port-conflict record did not shrink at all, and **`SYS:` is load-bearing** — without it `translateTime` formats in UTC, silently
  - **Proxy versus backend CORS** — decided in Task 1.8.3, backend CORS, so this records a decision rather than resolving one. State the Story 1.12 consequence (a proxy would leave 1.12's allowlist testing nothing in the one environment anybody runs) **and the measurement that actually settled it**, which the brief did not anticipate: through a proxy `x-request-id` reads back with no configuration at all, because a same-origin response exposes every header, so a proxy hides the correlation id's absence as well as the allowlist's. The proxy was built and run before being rejected. Two consequences belong in the write-up: **CORS is not this API's access control** — the server asserts the allowed origin to every caller and the browser is the only party that compares, so `curl` cannot test it — and `@fastify/cors`'s `methods` default is `GET,HEAD,POST`, so the first route taking a `PUT` needs that line
  - **Why the frontend's ports are literals** — decided in Task 1.8.4, not reversed, so this records a decision rather than resolving one. The alternative it beat is symmetry with the backend, explicitly rejected: `PORT`/`HOST` are properties of a deployed process and neither Vite port reaches a deployment at all. The consequence worth the write-up is that the reversal is now **two edits rather than one** — the port and the `CORS_ORIGIN` it is pinned to — and that its mechanism is `loadEnv()` and never `process.env`, because `vite.config.ts` cannot see a `.env` file at all. `strictPort` is right either way and its own consequence has a name now: a busy 5173 exits 1 and takes all of `pnpm dev` with it, while a busy 3000 does not stop anything
  - **How readiness is determined** — `pnpm ready` / `scripts/check-ready.mjs`, no dependency, and deliberately **not** a `verify` step. There are **four** independent reasons it cannot be a log grep, not two: the silence at `warn` and above; Fastify rewriting `0.0.0.0` to `127.0.0.1` in its own startup line; that line arriving _second_, after Vite's banner; and Task 1.8.2 changing its clock format, so a matcher written against the old shape matches nothing. Two consequences belong in the write-up. **Vite's dev server never 404s**, so no HTTP status can judge the frontend — `/`, `/src/main.tsx` and a type-only-importing module all answer 200 against a broken graph, and a module path that does not exist answers 200 `text/html` — which is why the check reads the **content type** of a module with a _value_ import of `@marketpulse/shared`. The terminal-crowding argument does not survive measurement (the banner is 12 startup lines and survives pnpm's prefix intact); what decides it is that **Storybook does not strict-port**, so a busy 6006 silently becomes 6007 — the behaviour `strictPort: true` exists to prevent for 5173 and 4173

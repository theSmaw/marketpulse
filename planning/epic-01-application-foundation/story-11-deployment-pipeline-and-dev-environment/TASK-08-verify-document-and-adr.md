## Work

- **Re-read the probe configuration off the deployed app rather than citing any number in this tree.** Task 1.11.3 replaced the platform's TCP defaults with HTTP probes against `/health`, which moved the readiness failure window from about four minutes to about **30 seconds** — and Task 1.11.7 was written against the old figure and had to be amended. That is this repository's citation-rot failure arriving inside one story rather than across six, so treat every probe number as a reading rather than a fact.
- **One cost question was left open on purpose and this is where it gets answered.** The health probes are the entire traffic and log volume of an idle deployment — roughly 16 records a minute. Whether continuous probing also breaks the Consumption plan's **idle billing** condition ("the replica isn't processing any HTTP requests") was deliberately not asserted in either direction, because the bill is the only arbiter. By now there is one. Read it, and say whether the $4.21 estimate held.
- **Re-take the cost figures, and treat them as the class of thing that rots fastest.** Task 1.11.3 read every rate from the Azure Retail Prices API rather than the pricing page, which renders its numbers in JavaScript, and produced an expected bill of about $9.21/month. Those are somebody else's prices on somebody else's release schedule and the account's free-tier offers expire on a clock that started at signup. Re-read them the same way rather than citing this task, and confirm the budget and the cost alert Task 1.11.3 set are still in place — a budget is repository-invisible configuration in exactly the way Story 1.10's ruleset is
- **Re-run every acceptance criterion, and re-take every figure.** This is the Story 1.10 pattern and it exists because citation rots: that story's closing task found a badge state that had expired, a heading count that had been counting the wrong thing, and eight copies of a convention that had quietly become false. So merge something and watch it deploy, request `/health`, deep-load a route and a made-up path, make the cross-origin call from a browser, read the cache headers again, and compare the deployed frontend's **four** files against a fresh local build — **with the variable set, or the comparison fails for the right reason and reads as a wrong one.** Since Task 1.11.5 the bundle carries `VITE_API_BASE_URL` as a string literal, so a plain `pnpm build` produces 344,537 B / `3c886f88…` and the deployed artefact is 344,609 B / `7654c2e0…`. Reproduce the deployed one with `VITE_API_BASE_URL=<the backend's origin> pnpm build`; a bare comparison is a 72-byte mismatch that looks like a broken deploy and is not
- **Re-take the frontend artefact's figures rather than carrying them, and re-run the sweep rather than trusting that it was complete.** This story is the first thing in six stories to change that artefact, and **Task 1.11.4 has already made the change and done the sweep**: `staticwebapp.config.json` reaches the root of the build output through Vite's `publicDir`, so `dist/` is **four files and 355,985 B**, the three original files are unchanged and byte-identical when downloaded back from the CDN, and every standing three-file claim was corrected while the historical measurements were left as history. **That is exactly the kind of claim this task exists to distrust.** Re-`grep` for the byte counts and for `three files` yourself; the distinction 1.11.4 drew — a present-tense invariant is corrected, a past measurement is left as history — is a judgement call made by one reader in one sitting, and the count somebody remembers has been wrong twice in this repository. Note also the one place the figure updates itself: the workflow's fingerprint step walks whatever `dist/` holds rather than naming the files, so it printed four rows with no edit.

Keep the existing honesty about what a green tick means; a deploy badge, if one is added, needs the same treatment — say what it certifies and what it does not
- **Update `CLAUDE.md`**: current state, the file tree (this story adds files — a container definition, platform configuration, possibly a deploy workflow), the Commands section if anything new is runnable, and the deployment facts that belong in the operational summary
- **Re-date the `pnpm verify` gap list and enlarge it honestly, because this story makes it worse in a new way.** The list is currently six entries, and the newest of them is `.github/workflows/verify.yml`, whose formatting Prettier checks and whose schema nothing does. Anything this story adds is the same shape or worse: a `Dockerfile` is read by no tool here at all (the `scripts/dev.sh` case), a platform configuration file may or may not have a Prettier parser — **check it with `prettier --file-info` rather than guessing**, which is the one-liner that separated the workflow from the shell script. **One of this bullet's two predictions is already settled and the other is not.** Task 1.11.2 measured the container half rather than predicting it: `apps/backend/Dockerfile` **and** the root `.dockerignore` both report `"inferredParser": null` to Prettier and no matching configuration to ESLint, so the `scripts/dev.sh` entry is now **three files** rather than one, and `hadolint` is declined and dated 2026-09-03. ~~That leaves one prediction to test rather than assume: `staticwebapp.config.json` is JSON and so is probably **inside** the net, which would make it the first platform configuration this repository actually checks.~~ **Settled by measurement in Task 1.11.4, and the prediction being right is the less interesting half.** `prettier --file-info apps/frontend/public/staticwebapp.config.json` reports `"inferredParser": "json"`, so it **is** the first platform configuration this repository checks and a malformed edit fails `format:check` by name. **The interesting half is what that check is worth**: nothing validates the schema, so a misspelled `navigationFallback`, a typo'd key inside a `routes` entry, or an `exclude` glob that matches nothing is green locally and silent in production — the same shape as the workflow's unchecked schema, and the same declined-tool answer. **And there is a specific live trap that no tool of either kind would catch**: the `exclude` array is `["/assets/*"]`, exact today because Vite puts every hashed asset there, and a file added to `apps/frontend/public/` lands at the artefact's **root** outside it — measured, `/favicon.svg` comes back as `index.html` at 200 rather than 404. A check for that — every non-config file in `public/` is covered by an `exclude` pattern — is one small script away; **decide it here rather than leaving it implied**, noting that with exactly one file in `public/` today it is scaffolding ahead of the iteration that needs it. **Task 1.11.5 added a new entry and it is the third kind of gap rather than the first — a stated invariant nothing enforces.** The frontend's environment boundary now has three enforcers (`envPrefix` at build time, `pnpm env:check` on the example file, and the compiler at the reading site via `strictImportMetaEnv` in `apps/frontend/src/vite-env.d.ts`), which is one more than it had. The cost is that **every variable is declared in two places and nothing checks the pair**: `scripts/check-env-example.mjs` reads `.env.example` and has no view of the declaration file, so a variable added to one and not the other is green. Today that pair is one variable long and the two agree. **Count it and decide it rather than describing it** — extending that script to parse the `.d.ts` is a small change to a file `verify` already runs, and Story 1.12 brings the second variable, which is where a pair becomes a set and the gap starts to matter. **And one entry moved the other way, which is the first time this list has shrunk**: Task 1.11.3 replaced `pnpm image`'s one-line recipe in `package.json` with `scripts/build-image.mjs`, so the tag rule, the `--platform` flag and the `.nvmrc` build-arg tie are now in a `.mjs` file that ESLint and Prettier both read, rather than in unchecked shell inside a JSON string. Count that rather than describing it — the two `clean` scripts still carry `rm -rf` inside JSON strings, so the "shell in a JSON string" entry is **narrower** than it was and is not gone. Check it with `prettier --file-info`; do not inherit the guess. It does ship inside `dist/`, and the second-order effect is worth stating precisely rather than loosely: the **source** is `apps/frontend/public/staticwebapp.config.json`, which Prettier formats and git tracks, and the **copy** in `dist/` is gitignored build output — so it is not one file wearing two hats, it is a source file with a build-produced twin, which is a shape nothing else here has and which means `pnpm clean` deletes the copy and not the original. **Storybook's build produces a third copy**, in `storybook-static/`, because `.storybook/main.ts` reuses `vite.config.ts` and inherits its `publicDir` — harmless while the workshop is unpublished, and the reason the SWA CLI reported finding the wrong one during 1.11.4's first deploy. And a deployed URL in prose is a figure nothing verifies. Count the new entries rather than describing them, and record the tool decisions (`actionlint` and `shellcheck` are both declined and dated; a third decline needs the same treatment)
- **Write `docs/adr/0011-*`.** It is the eleventh, and the numbering convention is in `docs/adr/README.md`. What it must record, each with the alternative that was rejected: the hosting choice for both halves and what the reversal costs; the two artefact shapes and why `pnpm deploy --filter` answers one and is meaningless for the other; the container start command and why it is not `pnpm start`; the `linux/amd64` requirement and the build-arg tie to `.nvmrc`; **the PID 1 finding as measured rather than as folklore** — the shell form does _not_ swallow `SIGTERM` on this image, because busybox `sh` execs a lone command and the base image's entrypoint ends in `exec "$@"`, and what actually swallows it is a shell with work left after the server, at the cost of a full 30-second grace and a `SIGKILL`; **`pnpm deploy --legacy` over `injectWorkspacePackages: true`**, which is a decision about every developer's install rather than about deployment, with pnpm removing the flag as its reversal trigger; **the `files` field on two manifests**, which is what stops the artefact shipping the coverage report and the test sources; **the container registry choice and its authentication** — including that it was taken on managed identity with `acrPull` rather than on price, and the measured finding that the registry costs _more_ than the compute it serves; **what a commit-SHA tag is allowed to mean**, and why a dirty tree gets a suffix rather than a refusal; **which of the two digests is the provenance record**, given that the image is an OCI index rather than a single manifest; **`minReplicas: 1`, which is the setting the whole Epic 3 argument rests on**; **`HOST=0.0.0.0` as a deployment requirement rather than a preference**, because the `127.0.0.1` default binds the container's own loopback and is unreachable by the ingress proxy while looking healthy from inside; **the replacement of the platform's default TCP probes with HTTP probes against `/health`**, and that a TCP probe passes on any process that binds the port; **that no platform secret was needed**, with the `secretRef` mechanism identified for Epic 2 rather than created for symmetry; **`version` left reporting `0.0.0`**, because the tag and digest already answer "what is deployed" and the obvious fix would dirty the tree the tag rule needs clean; the fallback's scoping and why a blanket catch-all was refused, **with the `exclude` array's scope stated as the live limitation it is** rather than as a solved problem; the cache policy, **and specifically why the document's `no-cache` is a `globalHeaders` entry and not a route rule** — route rules are not applied on requests that trigger `navigationFallback`, so the obvious shape would have covered `/` and none of the four routes; **that Static Web Apps is not offered in East US**, so the two halves are not co-located and the one-provider decision never implied one region; **that a Static Web Apps deploy is not atomic** — reproduced on two deploys, the outgoing asset withdrawn while the outgoing `index.html` is still served, a ~1.5-second window in which a cold load is broken, and no flag that removes it — which is the frontend's half of the failed-deployment criterion and reads as the opposite of the backend's revision model; **that both documented preview-environment hostname patterns were wrong and the environment name is normalised**, so a preview origin cannot be derived from a branch name and every preview environment is outside an allowlist that holds one string; **the deployment-token divergence** — used once by hand, stored nowhere, and whether it survived into the pipeline or was replaced by the federated credential Task 1.11.6 owes; **the per-environment build consequence**, which is the decision most likely to be re-litigated later — and it now has numbers behind it rather than a principle, because Task 1.11.5 measured CI's artefact and the deployed artefact differing by 72 bytes over one string literal; **what crossed the frontend-to-backend boundary in a deployment story and what was deliberately left to Story 1.12**, because a deployment story landing a data layer is the failure that decision avoided; **that `exposedHeaders` is load-bearing**, proven by the correlation id read in a browser matching the `reqId` in the backend's log — and that Story 1.8's rejection of a Vite proxy is what preserved that requirement rather than hiding it; **that a wrong `CORS_ORIGIN` and a forgotten `VITE_API_BASE_URL` are both green everywhere and broken only in a browser**, which is the honest limit of everything else in this ADR; **the typed `ImportMetaEnv`**, which closed a silent-failure class no tool in `verify` could see, at the stated cost of two declaration sites nothing reconciles; where the deploy runs and why it does not re-define the build; the failure and rollback behaviour, including the asymmetry between the two halves; the database decision; and the publish-the-workshop decision. **`HOSTING.md` is the input rather than a second copy** — the ADR records why, and should not restate the quoted limit tables, but it does owe one thing that document cannot have: **Epic 10's four-minute SSE constraint**, which is a decision taken in a deployment story that binds an epic nine stories away and will otherwise be discovered by an agent stream dying in production

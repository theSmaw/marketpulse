# Task 1.5.6 — Verify the story end to end, document it and record the decision

**Status:** Not started
**Story:** [1.5 Application Layout & Routing](STORY.md)
**Depends on:** Task 1.5.5

## Objective

Prove the story's criteria against a clean tree, write the conventions down where the next author will find them, and record the routing and layout decisions as an ADR. This is the story's acceptance test.

## Work

- **Verify from a clean build, not a warm one.** `pnpm clean && pnpm install && pnpm verify`, then `pnpm build`, then serve `apps/frontend/dist` with `python3 -m http.server` from **outside** the workspace — not `vite preview`, whose SPA fallback hides exactly the failures this story is most exposed to
- **Check each acceptance criterion by doing it**, in a browser: all four routes, the not-found state, the chrome surviving every navigation, the focus outline on every interactive element, the active-route indication without colour, and the §9 regions at the stated design width. Task 1.5.4 has already run four of these against the built page on a static host and recorded the numbers, so this is a re-run on a clean build rather than a first attempt — and it left a method for the region check too: `resize_window` did not change the reported `innerWidth` on this display, so the narrower width was measured inside an iframe of exactly 1280 px. **Use Task 1.5.3's method for "survives navigation" rather than looking at the page**, because a chrome that is remounted on every navigation looks identical to one that is not: stamp the `<header>` with a dataset attribute, navigate through all four routes and an unknown path, and check the attribute is still there — it proves the same DOM node, which "the header is still visible" does not. `performance.timeOrigin` unchanged is the companion proof that none of it was a document load
- **Re-measure the artefact and the timings.** Modules, JS, CSS and file count against the story's 193 / 300.09 kB / 7.21 kB / 3 baseline, against Task 1.5.1's measured router cost of 253 / 337.82 kB, against Task 1.5.2's shipped 261 / 340.10 kB / 8.62 kB / 3, against Task 1.5.3's shipped 263 / 340.83 kB / 9.13 kB / 3, and against **Task 1.5.4's shipped 265 / 342.08 kB / 9.82 kB / 3** — five figures rather than two, which is what separates what the router cost, what the routes cost, what the chrome cost, what the regions cost and what this task's splitting decision costs. The chrome's and the regions' shares are both small enough to be worth stating as such: **+2 modules and +0.73 kB** for the chrome and **+2 modules and +1.25 kB** for the regions, no new dependency in either, and still exactly one file importing `@base-ui/react`; `pnpm verify` against 10.5s from a clean tree; HMR against the two figures Task 1.4.6 established — CSS-only 24–130 ms, component 177–280 ms warm — with the same method (`performance.timeOrigin` unchanged proves it was HMR and not a reload) and the same caveat (a hidden tab throttles React's scheduler, so measure in the foreground or state the bound). Story 1.10 inherits the `verify` number
- ~~**Report what the React Compiler rules finally said.**~~ **They said it in Task 1.5.1, before this task's turn came.** `react-hooks/set-state-in-effect` failed `lint` at **error** on a spike route mirroring a URL parameter into state; the router itself provoked nothing, and the same route without the effect lints clean. So the standing question is answered and this task inherits a narrower one: **report what the rules said across Tasks 1.5.2 to 1.5.5** — whether anything fired in code that shipped rather than in a spike that was thrown away, and whether `--max-warnings 0` cost anything real. **Tasks 1.5.2, 1.5.3 and 1.5.4 have already answered their share: nothing.** Five route modules and the shell carry zero hooks and zero state between them, and the chrome — which had the two shapes most likely to attract the rules, a clock and a connection status — holds neither, because the clock is a reserved region and the status is a prop. Task 1.5.4 came closest without touching them: `Region` calls `useId()`, which is the **first hook in this application**, and the rules were silent because `useId` is not state. Silence across four tasks of shipping code — one of them now containing a hook — is itself the finding, and it means the 17 rules taken wholesale in Task 1.3.2 are still cheap — but note what that silence is evidence _of_: **this story has had almost nothing to hold state about**, which is a fact about the code rather than about compatibility with the rules, and Epic 2 is where it stops being true
- **Write the conventions where they will be read.** `CLAUDE.md` gets the operational half — the file tree with the routes and the chrome in it, where route modules live and why, the workshop's router decorator, the `App.tsx` exemption boundary this story settled, the route-path table and what it does and does not close, and the re-measured figures. Tasks 1.5.1 to 1.5.3 already wrote most of that there — the `react-router-dom` trap, the `react >=19.2.7` peer margin, the no-plugin rule, the `src/routes/` and `AppHeader/` entries in the file map, the path table, the `cx()`/TS2375 door, the shipped artefact figures, **the workshop-boundary rule and its one-directional enforcement, the `MemoryRouter` decorator and the `preview.ts` → `preview.tsx` rename, the landmark/permutation-grid conflict, and the re-measured focus outline across the chrome** — and Task 1.5.4 added the `Region` entry in the file map, the named-landmark decision with its axe figures against the **built page rather than a story**, the `height`-not-`min-height` finding, and the note that `useId` is the first hook here. **Check and correct them rather than restating them.** The current-state paragraph was updated by Task 1.5.3 and will be wrong again the moment the regions land, which is the one line in that file guaranteed to need editing. `README.md` gets whatever a human needs to run and look at it. Neither gets the reasoning; that is the ADR's
- **Write the ADR with the next free number, checked rather than assumed.** `docs/adr/` holds 0001–0004 as of 2026-08-31, so **0005** — confirm it at the time, and add the row to `docs/adr/README.md`. ADRs are numbered in the order written and never renumbered. Follow 0001's shape: context, decision, rejected alternatives **with the reasons they lost**, and the consequences a future reader would otherwise discover by tripping over them
- **The consequences worth stating plainly** are the ones this story cannot resolve inside itself: the deep-linking fallback is a host property and Story 1.11 owns it; route splitting changes the artefact from a file into a directory with absolute paths; and the region structure is what Story 1.7's local failure containment will be built against — four named landmarks in `MarketOverview`, each scrolling its own overflow, so an error state goes inside one without the other three moving
- **ADR 0005 carries Task 1.5.1's decision as well as this story's layout ones, and does not give it a number of its own** — the same way 0004 covered both the component library and the workshop. Its rejected-alternatives section is TanStack Router, the file-based plugin and `wouter`, with the reasons they lost taken from Task 1.5.1's Outcome rather than from memory, and its reversal triggers are that task's. **Two of this story's layout decisions belong in it as decisions rather than as description.** The regions are **named `region` landmarks** — `aria-labelledby` at the heading, ids from `useId()` — and the rejected alternative is plain `<div>`s, which is cheaper and leaves a keyboard or screen-reader user nothing to jump between on the screen the product opens on; the axe figures from Task 1.5.4 are the evidence. And the region grid takes a **`height` rather than a `min-height`**, because `fr` rows size to their content under a minimum and §9's proportions disappear — the consequence being that a region scrolls its own overflow and that Epic 6's canvas has a box with a resolved size. **One further consequence belongs there that this story did not choose**: React Router's `to` is an unchecked string, so the route-path table from Task 1.5.2 is a mitigation rather than a fix, and a typed router is the standing answer if mistyped paths become a real defect
- Update `EPIC.md` with what this story establishes for the stories after it — 1.7 and 1.12 most immediately, both of which were written expecting regions and a chrome that did not exist
- **Answer the question Task 1.4.6 asked of this story, and note Task 1.5.3 has already produced one answer.** Story 1.4 was documented on the bet that its first consumer would not need to ask it anything. It mostly held — the tokens, `FeedIndicator`, the focus rule and the `cx()` idiom were all used as written. **What was missing was a seam rather than a document**: the workshop wired no providers, so the first chrome component could not render in it at all, and Task 1.5.3 added the `MemoryRouter` decorator. That is a Story 1.4 gap found by Story 1.5, and the retrospective home for it is ADR 0004 — which describes the workshop — rather than 0005. Decide where it lands, record the second-order finding with it (the permutation-grid convention and landmark uniqueness are in direct conflict for any component that is itself a landmark, and the grid is what gives), and add **Task 1.5.4's finding, which is a third and a different kind**: Story 1.4's token layer is spacing, type and colour and has **no ladder for proportion** — no grid fractions, no page-height convention — so the region grid is the first stylesheet in this application that carries values which are not tokens. That is not a defect in the tokens; it is a boundary nobody had drawn, and drawing it (layout is proportion, design language is not) is what stops the next author inventing a `--layout-primary-ratio` nobody else uses
